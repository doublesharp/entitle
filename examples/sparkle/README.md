# Sparkle 2

Add Sparkle to your macOS application using its supported package workflow and
copy `LicenseUpdates.swift`. Set API/product constants and merge the Info.plist
fragment. Embed the Ed25519 public key generated by Sparkle's tools. The private
key stays in the seller build system. Sign each final ZIP/DMG with `sign_update`,
publish it under the correct darwin target, and pass its EdDSA signature string
in release metadata. Configure your application's code signing and hardened
runtime as required by Sparkle. Never remove native signature verification.

Retain one `LicenseUpdates(target: "darwin-universal")` instance from your app
delegate or settings model. On launch call `startUpdates()` if a token exists;
on settings submission call `try await activate(key:label:)`. Wire the normal
Check for Updates menu item to `checkForUpdates()`. Sparkle owns the download,
signature verification, install consent and relaunch UI. Wire a protected
settings action to `try await deactivate()` and display caught localized errors
without logging their underlying objects. Cancel or finish an active Sparkle
update before deactivating. The template checks that precondition.

Dynamic appcast selection uses `SPUUpdaterDelegate.feedURLString(for:)`; the
updater's read-only `feedURL` property is never assigned. Normal no-update and
user-cancellation outcomes do not display licensing failures.

The UUID lives in user defaults and survives app updates/deactivation; activation
tokens live in Keychain and license keys are not retained. `SPUUpdater.httpHeaders`
applies authentication to the appcast and package downloads. The server emits
only this product's same-origin immutable asset URLs, inline notes and no
redirects. Use only this configured feed and do not load external release-note
links with these headers. API requests explicitly reject redirects. No system
profile or hardware identity is collected. An update-service error or expired
license never disables installed functionality.

Use the release SemVer for both your app's CFBundleVersion and the published
version in this initial adapter. Separate internal build numbers are not modeled.
Match the updater target to the architecture the bundle actually supports, and
set minSystemVersion metadata when a release raises its macOS requirement.

Official interfaces: [Sparkle publishing](https://sparkle-project.org/documentation/publishing/),
[SPUUpdater HTTP headers](https://sparkle-project.org/documentation/api-reference/Classes/SPUUpdater.html).
Qualification: the native signed appcast format is unit tested. The Swift source
passes a real typecheck against the locally installed Sparkle 2.9.1 framework;
template regressions cover delegate feed selection and expected no-update /
cancellation filtering. A linked and running seller app, Keychain access, actual
EdDSA validation, update installation and relaunch remain unqualified.
